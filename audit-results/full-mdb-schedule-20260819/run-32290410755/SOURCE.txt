WHY THE PUBLISHED LEDGER NUMBERS ARE WRONG
------------------------------------------
`benchmark/audit_all/md_parity_mapping.py` is a bridge that `exec`s the canonical module in
`spec-audit/`. An `exec` inherits the BRIDGE's `__file__`, so the canonical module resolved
`fp_adjudication.tsv` to `benchmark/audit_all/`, where no such file exists. `_fp_verdicts()`
returns an empty dict for a missing path — silently, with no error — so every adjudicated
Analyzer rule came back "No verdict recorded" and this run republished settled rows as fresh
divergences. A second gap compounded it: the `analyzer_spec_unmapped` bucket asked no ledger
at all, so the 17 NO_MD_EQUIVALENT decisions from #165 were invisible too.

Both are fixed in the commit that publishes this directory, and the run did NOT need to be
repeated: the raw per-feed rows in `all-results.json.gz` are exactly the shard input, so
`aggregate.py` was re-run over them locally in four seconds. `reaggregated/` holds that
output. The top-level files are the run's own artifacts, unedited.

  analyzer_mapped_md_absent          14,980          4,993
  analyzer_spec_unmapped                690            327

None of those drops is a product improvement. They are already-judged divergences finally
