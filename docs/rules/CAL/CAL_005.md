# CAL_005 — start_date end_date'den sonra

> **Karar:** `calendar.txt` satırında `end_date`, `start_date` değerinden önce. KRİTİK, Interop (yayın engelleyici DEĞİL). **Düzeltme:** `end_date` değerini `start_date` ile aynı gün veya daha sonra olacak şekilde düzeltin.

## Tetikleme koşulu (kesin mantık)
`k2::calendar::validate_calendar()` içinde:
```
start_date parse edildi
VE end_date parse edildi
VE end_date < start_date
→ CAL_005
```
- Karşılaştırma `yyyymmdd` sayısal değeri üzerinden yapılır.
- `end_date == start_date` geçerlidir; kural yalnızca `<` durumunda çıkar.
- `start_date` veya `end_date` geçersizse CAL_005 çalışmaz.

## Yanlış pozitif / negatif (asıl tasarım riski)
- **Yanlış negatif:** Tarihlerden biri parse edilemezse CAL_005 çıkmaz; asıl root cause CAL_003/CAL_004 olur.
- **Yanlış pozitif:** Yok denecek kadar düşük; bitiş tarihi başlangıçtan önce olamaz.
