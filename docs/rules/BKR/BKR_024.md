# BKR_024 — booking_type=1 ve duration_max varken prior_notice_start_day yasak

> Karar: Aynı gün rezervasyonunda (`booking_type=1`) `prior_notice_duration_max` tanımlıysa
> `prior_notice_start_day` **yasaktır**. Spec: *"Forbidden for `booking_type=1` if
> `prior_notice_duration_max` is defined."*

## Tetikleme koşulu (kesin mantık)

```
booking_type == 1  VE  prior_notice_duration_max DOLU  VE  prior_notice_start_day DOLU
→ BKR_024
```

Çelişki şudur: `duration_max` "kalkıştan en fazla N dakika önce" der, `start_day` ise
"rezervasyon N gün önce açılır". Aynı gün rezervasyonunda ikisi birbirini dışlar.

## Karışan komşular (ayrım)

| Kural | Ne yakalar | Eksen | Önem · Sınıf · Aşama |
|---|---|---|---|
| **BKR_024** | `type=1` + `duration_max` + `start_day` | üç alanlı çelişki | ORTA · Spec · K2 |
| **BKR_002** | `start_day` var ama `last_day` yok | eşlik zorunluluğu | — · Spec · K2 |
| **BKR_005** | `type=2`'de `duration_max` yasak | tip bağlamı | — · Spec · K2 |
| **BKR_004** | `type=0`'da tüm prior_notice alanları yasak | anlık rezervasyon | — · Spec · K2 |
| **BKR_003** | `start_time` yalnız `start_day` ile | eşlik zorunluluğu | — · Spec · K2 |

`prior_notice_duration_max` parser'da üç yerde geçiyordu (`booking_rules.rs:129/137/157`) ve
hiçbiri `start_day` ile ilişkilendirilmiyordu; bu hükmün `booking_type=1` dalı tamamen
sessizdi.

## Yanlış pozitif / negatif
- **Yanlış pozitif:** Yok. Üç koşul da alanın varlığına bakar, yoruma değil.
- **Yanlış negatif:** `booking_type` geçersizse (`BKR_016`) bu kural susar — tip bilinmeden
  bağlam kurulamaz.
