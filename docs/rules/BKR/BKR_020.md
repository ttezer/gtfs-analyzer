# BKR_020 — booking_url geçersiz

> **Karar:** `booking_rules.txt.booking_url` dolduğunda geçerli bir `http/https` URL olmalıdır. ORTA, Spec.
> 📌 Bu alan `k1_parse::known_columns` listesinde vardı — yani "bilinmeyen sütun" uyarısı **almıyordu** — ama hiçbir denetim aşaması okumuyordu (issue #60). Değer sessizce geçiyordu. `booking_url` yolcunun rezervasyonu **fiilen yaptığı** adrestir; bozuksa hizmet rezerve edilemez.

## Tetikleme koşulu (kesin mantık)
```text
K2: booking_url dolu
VE looks_like_url(booking_url) false
→ BKR_020
```

## Yanlış pozitif / negatif (asıl tasarım riski)
- **Yanlış negatif:** Boş `booking_url` hata değildir (alan Optional).
- **Yanlış pozitif:** URL biçimsel olarak doğrulanır; gerçekten açılıp açılmadığı kontrol edilmez.

## Neden ORTA (info_url'in DÜŞÜK'ünden farklı)
`booking_url` eylem yoludur — yolcu oradan rezervasyon yapar. `info_url` (BKR_021) yalnız
açıklayıcıdır. Aynı dosyada aynı tipte iki alanın farklı önemde olmasının gerekçesi budur.

- **Kural mesajı:** booking_url geçersiz
- **Çözüm önerisi:** `booking_url` için geçerli bir `http/https` URL kullanın.

### R2 mesajı/mesajları
- **Ayrıntılı bulgu mesajı:** *"booking_url geçerli bir URL değil."*

## Ölçülen alan / değer
- **Dosya/alan:** `booking_rules.txt` → `booking_url`
- **Gözlenen değer:** geçersiz URL metni
- **Beklenen değer:** `http://` veya `https://` ile başlayan geçerli URL

## Kod değiştirirken minimum test matrisi
- `booking_url=https://example.com/book` → BKR_020 çıkmamalı.
- `booking_url=notaurl` → BKR_020 çıkmalı.
- `booking_url` boş → BKR_020 çıkmamalı.
- `info_url` bozuk → BKR_020 çıkmamalı (o BKR_021).
