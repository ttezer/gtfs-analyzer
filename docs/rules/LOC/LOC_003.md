# LOC_003 — Feature'da 'id' property eksik

> **Karar:** `locations.geojson` içindeki bir feature üst seviye `id` üyesi taşımıyorsa `stop_times.txt.location_id` ile güvenilir çapraz referans kurulamaz. KRİTİK, spec hatası. **Düzeltme:** Her feature'a `stop_times.txt` tarafından referanslanabilecek benzersiz bir `id` ekleyin.
> ⚠️ Kod `properties.id` alanına değil GeoJSON `Feature.id` üst seviye üyesine bakar; yanlış yere yazılan id bu kuralı düzeltmez.

## Tetikleme koşulu (kesin mantık)
`k1_parse::validate_locations_geojson()` içinde:
```
root.type == "FeatureCollection"
VE features dizisi boş değil
VE feature.get("id") yok
→ LOC_003
```
- Kontrol feature döngüsünde yapılır ve 1 tabanlı feature numarası verir.
- `id` değeri varsa bu kural değer biçimini denetlemez.
- Yinelenen `id` değerleri LOC_007 tarafından ayrıca yakalanır.

## Yanlış pozitif / negatif (asıl tasarım riski)
- **Yanlış negatif:** `id` var ama boş string veya anlamsız değer ise LOC_003 çıkmaz; benzersizlik varsa LOC_007 de çıkmayabilir.
- **Yanlış pozitif:** `properties.id` dolu olsa bile üst seviye `Feature.id` yoksa LOC_003 çıkar; kod ve GTFS Flex referans modeli üst seviye `id` bekler.

## Kod değiştirirken minimum test matrisi
- Feature üst seviye `id` yok → LOC_003 çıkmalı.
- `properties.id` var ama üst seviye `id` yok → LOC_003 çıkmalı.
- Üst seviye `id` var → LOC_003 çıkmamalı.
- İki feature aynı `id` değerini taşıyor → LOC_007 çıkmalı, LOC_003 ile karışmamalı.
- Boş `features` dizisi → LOC_005 çıkmalı, LOC_003 çalışmamalı.
