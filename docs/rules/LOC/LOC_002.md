# LOC_002 — Feature'da geometry null veya eksik

> **Karar:** `locations.geojson` içindeki bir feature için `geometry` alanı yoksa veya `null` ise GTFS Flex servis bölgesi tanımlanamaz. KRİTİK, spec hatası. **Düzeltme:** Her feature için geçerli `Polygon` veya `MultiPolygon` geometrisi ekleyin.
> ⚠️ Bu kural sadece `geometry` varlığını ölçer; `geometry.type` yanlışsa LOC_001, ring kapanışı bozuksa LOC_004 çalışır.

## Tetikleme koşulu (kesin mantık)
`k1_parse::validate_locations_geojson()` içinde:
```
root.type == "FeatureCollection"
VE features dizisi boş değil
VE feature.geometry yok veya null
→ LOC_002
```
- LOC_002 satır/feature numarasını `features` dizisindeki 1 tabanlı sıra olarak verir.
- LOC_002 üretildikten sonra o feature için geometri tipi ve ring kontrolleri atlanır.
- Feature `geometry` nesnesi var ama tipi eksikse LOC_001 üretir.

## Yanlış pozitif / negatif (asıl tasarım riski)
- **Yanlış negatif:** `features` alanı eksikse kod feature döngüsüne girmez; LOC_002 çıkmaz.
- **Yanlış pozitif:** GTFS dışı GeoJSON kullanımında `geometry:null` izinli olabilir; GTFS Flex lokasyon bölgesi için kabul edilmez.

## Ölçülen alan / değer
- **Dosya/alan:** `locations.geojson` → `features[*].geometry`
- **Gözlenen değer:** Alan yok veya `null`.
- **Beklenen değer:** `type` ve `coordinates` içeren geçerli `Polygon` veya `MultiPolygon` geometry nesnesi.

## Kod değiştirirken minimum test matrisi
- Feature içinde `geometry` yok → LOC_002 çıkmalı.
- Feature içinde `geometry:null` → LOC_002 çıkmalı.
- Feature içinde `geometry:{}` → LOC_001 çıkmalı, LOC_002 çıkmamalı.
- Geçerli `Polygon` → LOC_002 çıkmamalı.
- Kök `FeatureCollection` değil → LOC_001 erken dönüşü LOC_002'yi maskelemeli.
