# LOC_007 — FeatureCollection içinde yinelenen feature 'id'

> **Karar:** `locations.geojson` içinde iki feature aynı üst seviye `id` değerini kullanıyorsa `stop_times.txt.location_id` referansı hangi Flex bölgesine gideceğini belirsizleştirir. ORTA, spec hatası. **Düzeltme:** Her feature'a dosya içinde benzersiz bir `id` verin.
> ⚠️ Kod `id` değerini JSON temsilindeki string karşılığıyla karşılaştırır; aynı görünen farklı JSON tipleri beklenmedik eşleşme davranışı yaratabilir.

## Tetikleme koşulu (kesin mantık)
`k1_parse::validate_locations_geojson()` içinde:
```
root.type == "FeatureCollection"
VE features dizisi boş değil
VE feature.id var
VE aynı JSON-string id daha önce görüldü
→ LOC_007
```
- İlk görülen feature değil, tekrar eden sonraki feature için notice üretilir.
- `id` olmayan feature'lar LOC_003 tarafından ayrıca raporlanır.
- Kontrol yalnızca `locations.geojson` içi tekrarları yakalar; `stops.stop_id` veya `location_groups.location_group_id` ile çapraz benzersizlik bu kuralın kapsamı değildir.

## Yanlış pozitif / negatif (asıl tasarım riski)
- **Yanlış negatif:** `locations.geojson` içinde benzersiz olan ama `stops.stop_id` ile çakışan id bu kural tarafından yakalanmaz.
- **Yanlış pozitif:** Aynı id'nin bilinçli olarak iki geometriyi temsil etmesi istenmiş olabilir; GTFS referans modeli tekil id beklediği için bu belirsizdir.

- **Kural mesajı:** FeatureCollection içinde yinelenen 'id' değeri — Flex referansı belirsizleşir
- **Çözüm önerisi:** Her feature'a dosya içinde benzersiz ve `stop_times.location_id` ile eşleşebilir bir `id` verin.

### R2 mesajı/mesajları

## Ölçülen alan / değer
- **Dosya/alan:** `locations.geojson` → `features[*].id`
- **Gözlenen değer:** Aynı `id` değeri birden fazla feature'da geçiyor.
- **Beklenen değer:** `locations.geojson` içindeki her feature için benzersiz `id`.

## Kod değiştirirken minimum test matrisi
- İki feature aynı `id` değerini taşıyor → LOC_007 çıkmalı.
- Üç feature aynı `id` değerini taşıyor → ikinci ve üçüncü tekrarlar için davranış net kalmalı.
- Tüm feature id'leri benzersiz → LOC_007 çıkmamalı.
- Bir feature'da `id` yok → LOC_003 çıkmalı, LOC_007 ile karışmamalı.
- `locations.geojson` içi benzersiz ama `stops.stop_id` ile çakışan id → LOC_007 çıkmamalı; ayrı çapraz benzersizlik kuralı gerekir.
