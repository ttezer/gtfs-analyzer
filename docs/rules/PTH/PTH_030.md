# PTH_030 — Boarding area'sı olan platforma pathway atanmış

> Karar: Bir platformun boarding area'ları (`location_type=4`) modellenmişse pathway'ler
> **boarding area'lara** bağlanmalıdır. Spec: *"In such cases, the platform must not have
> pathways assigned."*

| Alan | Değer |
|---|---|
| Grup | PTH — Geçitler (pathways) |
| Önem | Düşük |
| Sınıf | Spec |
| Aşama | K4 |
| Varlık | Row |
| Kimlik alanı | `pathway_id` |
| Skor tabanı | 1 |
| Görünürlük | VS (`R2`, `R5`, `R9`) |
| Bloke ettiği kurallar | - |

## Tetikleme koşulu (kesin mantık)

```
P = { parent_station : location_type == 4 olan durakların üstleri }
pathway.from_stop_id ∈ P  VEYA  pathway.to_stop_id ∈ P
→ PTH_030 (her eşleşen uç için)
```

## Neden kural yoksa fark edilmiyordu

Grafik kodu iç içe modellemeyi **tolere ediyor**: `PTH_012` (istasyona erişilebilir yol yok)
bir platformu, çocuk düğümlerinden biri girişten erişilebiliyorsa erişilebilir sayıyor
(`k6_analytics.rs:7287` — Santiago Metro'da 286 yanlış pozitifi kapatan karar). Yani yanlış
modelleme sessizce çalışıyor, ama spec'in **yasağı** hiç ölçülmüyordu.

## Yanlış pozitif / negatif
- **Yanlış pozitif:** Düşük ama **ölçülmedi**. Endişe, iç içe modellemenin yaygın olması ve
  kuralın gürültü üretmesiydi; korpusta örnek çıkmadı, yani en azından bu 239 feed'de
  gürültü yok.
- **Yanlış negatif:** Boarding area'sı olmayan platformlar kapsam dışıdır (hüküm yalnız
  o durumda konuşur).

## Mesaj & çözüm önerisi
### R9 Kural Mesajı
- **Kural mesajı:** Boarding area'sı olan platforma pathway atanmış
- **Çözüm önerisi:** Pathway'i platformun boarding area'sına (`location_type=4`) bağlayın.

### R2 mesajı/mesajları
- *"pathway 'W1' to_stop_id='P1' platformuna bağlanıyor ama o platformun boarding area'ları
  tanımlı — pathway'ler boarding area'lara bağlanmalıdır."*

## Ölçülen alan / değer
- `field`: `from_stop_id` veya `to_stop_id` · `observed`: platform `stop_id`'si
