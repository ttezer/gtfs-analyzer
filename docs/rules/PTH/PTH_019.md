# PTH_019 — Generic node tek pathway'e bağlı (dead-end)

> **Karar:** `location_type=3` generic node yalnızca tek pathway bağlantısında geçiyorsa geçiş ağında çıkmaz düğüm oluşur. ORTA, kalite sorunu. **Düzeltme:** Generic node'u en az iki pathway ile bağlayın veya gereksiz düğümü kaldırın.
> ⚠️ Bu kontrol bağlantı sayısını from/to uçlarında sayar; pathway yönlülüğünü değil generic node'un ağdaki derece değerini ölçer.

| Skor tabanı | 2 |

| Bloke ettiği kurallar | - |

## Tetikleme koşulu (kesin mantık)
`k4_cross_ref::check_pathways()` içinde:
```
conn_count[stop_id] = pathway from_stop_id/to_stop_id geçiş sayısı
VE stops.txt satırı location_type == 3
VE conn_count[stop_id] == 1
→ PTH_019
```
- Sadece generic node (`location_type=3`) stop'lar değerlendirilir.
- Gözlenen değer `1`, beklenen değer `≥2`.
- Sıfır bağlantılı generic node bu kural tarafından yakalanmaz.

## Yanlış pozitif / negatif (asıl tasarım riski)
- **Yanlış negatif:** Hiç pathway bağlantısı olmayan generic node `count == 0` olduğu için PTH_019 üretmez.
- **Yanlış pozitif:** Tek bağlantılı generic node bilinçli placeholder olabilir; gerçek pathway graph'ta çıkmaz oluşturur.

- **Çözüm önerisi:** Generic node'u en az iki pathway ile bağlayın veya modelden kaldırın.

### R2 mesajı/mesajları
- **Ayrıntılı bulgu mesajı:** *"stop_id '{stop_id}' (generic node, location_type=3) yalnızca 1 pathway'e bağlı — geçiş ağında çıkmaz."*
- **Çözüm önerisi:** *"Generic node en az 2 pathway ile bağlanmalıdır (giriş ve çıkış)."*

## Ölçülen alan / değer
- **Dosya/alan:** `stops.txt` → `stop_id`, `location_type`; `pathways.txt` → `from_stop_id`, `to_stop_id`
- **Gözlenen değer:** `1`
- **Beklenen değer:** `≥2`

## Kod değiştirirken minimum test matrisi
- Generic node tek pathway'de geçiyor → PTH_019 çıkmalı.
- Generic node iki pathway'de geçiyor → PTH_019 çıkmamalı.
- Generic node sıfır pathway'de geçiyor → mevcut davranışta PTH_019 çıkmamalı.
- Platform/entrance stop tek pathway'de geçiyor → PTH_019 çıkmamalı.
