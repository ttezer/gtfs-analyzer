# STM_049 — Aynı satırda gece yarısı sonrası kalkış 00:xx yazılmış (GTFS servis günü için 24:xx kullanılmalı)

> Karar: Bir durakta gece yarısını aşan kalkış `24:00:00+` yerine `00:xx` yazılmışsa (aynı satırda kalkış varıştan önce görünür) GTFS Spec bulgusu verilir. STM_007'nin analitik yanlış-pozitifi ayrıca config'e göre bastırılabilir. BİLGİ, Spec.

| Alan | Değer |
|---|---|
| Grup | STM — Stop Times |
| Önem | Bilgi |
| Sınıf | Spec |
| Aşama | K2 → K6 |
| Varlık | Feed |
| Kimlik alanı | `departure_time` |
| Skor tabanı | 1 |
| Görünürlük | VS (`R2`, `R5`, `R9`) |
| Bloke ettiği kurallar | - |

## Tetikleme koşulu (kesin mantık)
K2, her satırda `arrival_time > departure_time` ve büyük raw geri sıçrama varsa bunu aynı satırdaki `00:xx` kalkış olarak sayar. Bu raw Spec tespiti `service_day_start_hour`'dan bağımsızdır ve feed seviyesinde tek STM_049 özeti üretir. Downstream K6, `service_day_start_hour > 0` olduğunda aynı satırdaki STM_007 yanlış-pozitifini analitik olarak bastırmaya devam eder; raw Spec bulgusu bu ayardan etkilenmez.

Bu STM_007'nin (gerçek satır-içi hata) normatif tamamlayıcısıdır.

## Yanlış pozitif / negatif (asıl tasarım riski)
- Raw Spec bulgusu normalization ayarına bağlı değildir. Küçük gün-içi `departure < arrival` hataları (ör. `08:00 → 07:55`) STM_007'ye bırakılır.

## Mesaj & çözüm önerisi
### R9 Kural Mesajı
- **Kural mesajı:** Aynı satırda gece yarısı sonrası kalkış 00:xx yazılmış (GTFS servis günü için 24:xx kullanılmalı)
- **Çözüm önerisi:** Gece yarısını aşan kalkış saatlerini 24:00:00+ biçiminde yazın (00:xx yerine).

### R2 mesajı/mesajları
- **Ayrıntılı bulgu mesajı:** *"<N> durakta departure_time ham feed'de 00:xx yazılmış; GTFS servis günü için 24:00:00+ biçimi kullanılmalıdır. STM_007 analitik yanlış-pozitifi config'e göre ayrıca bastırılabilir."*

## Ölçülen alan / değer
- `file`: `stop_times.txt`
- `observed`: raw same-row rollover olarak tanınan durak sayısı
- `expected`: `24:00:00+`

## Kod değiştirirken minimum test matrisi
| Senaryo | Beklenen |
|---|---|
| kalkış ≥ varış (normal) | `STM_049` yok |
| kalkış < varış ve büyük raw geri sıçrama | `STM_049` BİLGİ·Spec; `start_hour>0` ise STM_007 bastırılır |
| kalkış < varış, küçük gerçek hata | STM_007 (STM_049 yok) |
| service_day_start_hour = 0 | `STM_049` yine var; yalnız STM_007 bastırması kapalı |

## Teknik ek
### Skora katkı
`Bilgi`, taban 1: teorik skor katkısı `1 * 0.0 = 0.0` (skoru etkilemez, yalnız bilgilendirir).

### Hangi raporlarda görünür
`VS`: `R2`, `R5`, `R9`.

### Bağımlılık (bunu maskeleyen root cause'lar)
- `service_day_start_hour = 0` yalnız downstream STM_007 bastırmasını/normalizasyonu etkiler; raw STM_049 Spec tespiti açık kalır.

### Dış araç eşleşmesi
- MobilityData bu raw yazım ihlalini ayrı bir parite koduyla raporlamaz; STM_049 doğrudan GTFS Schedule Reference dayanağıyla Spec sınıfındadır. STM_007 yalnız analitik same-row geriye gidiştir.

### GTFS spec referansı
- [GTFS Schedule Reference — `stop_times.txt`](https://gtfs.org/documentation/schedule/reference/#stop_timestxt): arrival_time ve departure_time için gece yarısından sonraki servis-günü saatleri `24:00:00` üstü `HH:MM:SS` biçiminde yazılmalıdır.
