# STM_048 — Gece yarısı sonrası saatler 00:xx yazılmış (GTFS servis günü için 24:xx kullanılmalı)

> Karar: Feed gece yarısını aşan saatleri `24:00:00+` yerine `00:xx` olarak yazmışsa GTFS servis günü notasyonu ihlal edilir. Raw değerler K2'de normalization'dan önce BİLGİ·Spec olarak raporlanır; analiz için saatler daha sonra otomatik `24:xx`'e normalize edilir.

| Alan | Değer |
|---|---|
| Grup | STM — Stop Times |
| Önem | Bilgi |
| Sınıf | Spec |
| Aşama | K2 → K6 |
| Varlık | Feed |
| Kimlik alanı | `arrival_time\|departure_time` |
| Skor tabanı | 1 |
| Görünürlük | VS (`R2`, `R5`, `R9`) |
| Bloke ettiği kurallar | - |

## Tetikleme koşulu (kesin mantık)
K2, `normalize_service_day` çalışmadan önce bir trip'in ham duraklar arası saatlerini `00:xx → 24:xx` rollover'ı olarak tanır. Feed'de en az 1 böyle trip varsa STM_048 (feed seviyesi BİLGİ·Spec) üretilir. Ardından normalization K6'nın zaman analizini korur. `config.service_day_start_hour = 0` ise bu rollover sezgisi ve normalization kapalıdır; bağımsız gerçek geriye-gidiş STM_008'e bırakılır.

Bu STM_008'in (gerçek geriye-gidiş) tamamlayıcısıdır: STM_008 elenen gece-yarısı vakalarının toplamı burada bilgi olarak raporlanır.

## Yanlış pozitif / negatif (asıl tasarım riski)
- `STM_048` raw feed'in servis-günü yazımını ölçer; normalization sonrası aynı olay STM_008 olarak tekrar üretilmez.
- `00:xx` gerçekten gece yarısı sonrası servis günü anlamındaysa yine hatalı yazımdır; üretici `24:00:00+` kullanmalıdır.

## Karışan komşular (ayrım)
| Kural | Ne yakalar | Eksen | Önem · Sınıf · Aşama |
|---|---|---|---|
| **STM_048** | Gece-yarısı aşan saatler `00:xx` (duraklar arası) | servis-günü notasyonu | BİLGİ · Spec · K2 |
| **STM_008** | Gerçek, normalization ile açıklanamayan geriye-gidiş | zaman monotonluğu (Interop) | değişken · Interop · K6 |
| **STM_049** | Gece-yarısı kalkış `00:xx` (aynı satır) | servis-günü notasyonu (bilgi) | BİLGİ · Quality · K6 |

## Mesaj & çözüm önerisi
### R9 Kural Mesajı
- **Kural mesajı:** Gece yarısı sonrası saatler 00:xx yazılmış (GTFS servis günü için 24:xx kullanılmalı)
- **Çözüm önerisi:** Gece yarısından sonraki saatleri 24:00:00, 25:00:00… biçiminde yazın; 00:xx kullanmayın.

### R2 mesajı/mesajları
- **Ayrıntılı bulgu mesajı:** *"<N> seferde gece yarısı sonrası saatler ham feed'de 00:xx olarak yazılmış; GTFS servis günü için 24:00:00+ biçimi kullanılmalıdır. Analiz için 24:xx olarak normalize edilecektir."*

## Ölçülen alan / değer
- `file`: `stop_times.txt`
- `observed`: ham feed'de rollover olarak tanınan trip sayısı
- `expected`: `24:00:00+`

## Kod değiştirirken minimum test matrisi
| Senaryo | Beklenen |
|---|---|
| tüm saatler artan | `STM_048` yok |
| `23:59:00 → 00:00:00`, service_day_start_hour>0 | `STM_048` BİLGİ·Spec, sonra K6 için `24:00:00`'a normalize |
| `23:59:00 → 24:00:00` | `STM_048` yok |
| `08:00:00 → 07:55:00` | `STM_048` yok; `STM_008` var |
| service_day_start_hour = 0 | rollover sezgisi/normalizasyon kapalı; `STM_048` yok |

## Teknik ek
### Skora katkı
`Bilgi`, taban 1: teorik skor katkısı `1 * 0.0 = 0.0` (skoru etkilemez, yalnız bilgilendirir).

### Hangi raporlarda görünür
`VS`: `R2`, `R5`, `R9`.

### Bağımlılık (bunu maskeleyen root cause'lar)
- `service_day_start_hour = 0` ise normalizasyon ve bu not kapalıdır.

### Dış araç eşleşmesi
- MobilityData servis-günü yazımını ayrı bir parite koduyla raporlamaz; `STM_048` doğrudan GTFS Schedule Reference dayanağıyla Spec sınıfındadır. `STM_008` ise normalization ile açıklanamayan zaman geriye-gidişleri için Interop paritesidir.

### GTFS spec referansı
- [GTFS Schedule Reference — `stop_times.txt`](https://gtfs.org/documentation/schedule/reference/#stop_timestxt): servis gününde gece yarısından sonraki saatler `24:00:00` üstü `HH:MM:SS` biçiminde yazılmalıdır.
