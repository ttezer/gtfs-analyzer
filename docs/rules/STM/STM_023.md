# STM_023 — stop_times satır sıralaması bozuk

> Karar: Aynı trip'e ait stop_times satırları dosya içinde `stop_sequence` artan sırayla görünmelidir.
> ⚠️ `stop_sequence` parse edilemezse önce STM_005 çözülmelidir.

| Alan | Değer |
|---|---|
| Grup | STM — Stop Times |
| Önem | Kritik |
| Sınıf | Spec |
| Aşama | K2 |
| Varlık | Row |
| Kimlik alanı | `trip_id` |
| Skor tabanı | 3 |
| Görünürlük | VS_K (`R1`, `R2`, `R5`, `R9`) |
| Bloke ettiği kurallar | - |

## Tetikleme koşulu (kesin mantık)
K2 her trip için son görülen `stop_sequence` değerini tutar.

Yeni satırdaki `stop_sequence`, önceki değerden küçükse STM_023 üretilir. Bu kural trip başına bir kez ateşlenir ve aynı bilgi K6'daki STM_036 için `unsorted_seq_trips` listesine de eklenir.

## Yanlış pozitif / negatif (asıl tasarım riski)
- **Yanlış negatif:** `stop_sequence` parse edilemezse önce STM_005 çözülmelidir.
- **Yanlış pozitif:** Dosya satır sırası önemsiz sanılabilir; ancak birçok tüketici stop_times'ı trip ve sequence sırasına göre bekler.

## Karışan komşular (ayrım)

## Mesaj & çözüm önerisi
### R9 Kural Mesajı
- **Kural mesajı:** stop_times satır sıralaması bozuk
- **Çözüm önerisi:** `stop_times.txt` satırlarını `trip_id` ve `stop_sequence` artan sırasına göre düzenleyin.

### R2 mesajı/mesajları
- **Ayrıntılı bulgu mesajı:** *"trip_id '<trip_id>' satırları stop_sequence sırasında değil: <curr> < <prev>."*
- **Ayrıntılı çözüm:** *"stop_times.txt'i stop_sequence değerine göre sıralayın."*

## Ölçülen alan / değer
- `file`: `stop_times.txt`
- `field`: `stop_sequence`
- `line`: sequence gerileyen satır
- `observed`: mevcut sequence
- `expected`: `> <önceki sequence>`

## Kod değiştirirken minimum test matrisi
