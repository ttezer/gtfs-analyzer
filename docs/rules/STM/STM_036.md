# STM_036 — stop_sequence değerleri sırasız

> Karar: K2'de saptanan sırasız `stop_sequence` bilgisi K6'da trip seviyesinde tekrar raporlanır.
> ⚠️ K2 `unsorted_seq_trips` listesine ekleme yapmazsa STM_036 üretilemez.

| Alan | Değer |
|---|---|
| Grup | STM — Stop Times |
| Önem | Yüksek |
| Sınıf | Quality |
| Aşama | K6 |
| Varlık | Entity |
| Kimlik alanı | `trip_id` |
| Skor tabanı | 2 |
| Görünürlük | VS (`R2`, `R5`, `R9`) |
| Bloke ettiği kurallar | - |

## Tetikleme koşulu (kesin mantık)
K2, STM_023 üretirken aynı trip bilgisini `unsorted_seq_trips` listesine ekler.

K6 bu listeyi okuyup STM_036 üretir. Yani STM_036 bağımsız yeni keşif değil, K2'de yakalanan sırasızlık bilgisinin entity/kalite raporu tarafındaki görünümüdür.

## Yanlış pozitif / negatif (asıl tasarım riski)
- **Yanlış negatif:** K2 `unsorted_seq_trips` listesine ekleme yapmazsa STM_036 üretilemez.
- **Yanlış pozitif:** STM_023 ile aynı kök nedene dayanır; raporlama düzeyi farklıdır.

- **Kural mesajı:** stop_sequence değerleri sırasız (unsorted_stop_times)
- **Çözüm önerisi:** `stop_times.txt` dosyasını `trip_id` ve `stop_sequence` artan sırasına göre düzenleyin.

### R2 mesajı/mesajları
- **Ayrıntılı bulgu mesajı:** *"'<trip_id>' seferinde stop_sequence <prev>'den <curr>'e düşüyor — değerler artmalı."*

- `line`: sequence düşüşünün görüldüğü satır
- `observed`: mevcut sequence
