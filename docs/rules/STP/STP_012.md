# STP_012 — stop_times'ta istasyon veya giriş kullanılmış

> Karar: `stop_times.txt` sadece fiziksel durak/platform kayıtlarına, yani `location_type` boş veya `0` olan `stop_id` değerlerine referans vermelidir.
> ⚠️ Bu kural `stop_times.txt`te kullanılan id stops içinde bulunduğunda tipini kontrol eder; id stops içinde hiç yoksa STM_002/STP çapraz referans hattı ayrı değerlendirilir.

| Bloke ettiği kurallar | - |

## Tetikleme koşulu (kesin mantık)
K4, `stop_times.txt` içinde kullanılan `stop_id` kümesini alır. Bu id `stops.txt` içinde varsa ama kaydın `location_type` değeri `1`, `2`, `3` veya `4` ise STP_012 üretilir.

## Yanlış pozitif / negatif (asıl tasarım riski)
- **Yanlış negatif:** `stop_id` stops'ta hiç yoksa bu kural değil STM_002 beklenir.
- **Yanlış pozitif:** İstasyon adını sefer durağı gibi kullanmak yolcuya mantıklı görünse bile GTFS modelinde geçersizdir.

## Mesaj & çözüm önerisi
### R9 Kural Mesajı
- **Kural mesajı:** stop_times'ta istasyon veya giriş kullanılmış
- **Çözüm önerisi:** `stop_times.txt` içinde yalnızca fiziksel durak/platform `stop_id` değerlerini kullanın.

### R2 mesajı/mesajları
- **Ayrıntılı bulgu mesajı:** *"stop_id '<id>' stop_times'ta kullanılıyor ama location_type=<loc_type> (sadece 0 veya boş olmalı)."*
- **Ayrıntılı çözüm:** *"stop_times'ta yalnızca location_type=0 (veya boş) olan durakları kullanın."*

## Ölçülen alan / değer
- `file`: `stops.txt`
- `field`: `location_type`
- `line`: ilgili stop satırı
- `observed`: stop_times'ta kullanılan non-platform id
- `expected`: `location_type=0` veya boş
