# STP_017 — İki durak birbirine çok yakın

> Karar: İki farklı durak yapılandırılmış yakınlık eşiğinin altında ama birebir aynı olmayan mesafedeyse kalite uyarısı üretilir.
> ⚠️ Eşik `config.stop_too_close_m` değerine bağlıdır; iki durak tam aynı koordinattaysa STP_017 değil STP_016 üretilir.

| Alan | Değer |
|---|---|
| Grup | STP — Stops |
| Önem | Düşük |
| Sınıf | Quality |
| Aşama | K6 |
| Varlık | Entity |
| Kimlik alanı | `stop_id` |
| Skor tabanı | 1 |
| Görünürlük | VS (`R2`, `R5`, `R9`) |
| Bloke ettiği kurallar | - |

## Tetikleme koşulu (kesin mantık)
K6 koordinatı olan durak çiftlerini karşılaştırır. Mesafe `0` değil ama `config.stop_too_close_m` eşiğinden küçükse STP_017 üretilir. **İstisnalar STP_016 ile ortaktır (sırayla):** Null Island bölgesi (kök neden GEO_016) · uçlardan biri `location_type` 1/2/3/4 (istasyon iskeleti) · parent/child çifti · aynı-parent kardeşler (bir istasyonun iki peronu).

## Değişiklik notu (2026-07-24 · kardeş + location_type daraltması)
Çok-feed denetiminde VBB'nin 5.427 yakın-çiftinin **%88'i aynı-parent kardeş perondu** — station-hierarchy modellemesinin tanımı gereği normal olan yakınlık FP üretiyordu. Kardeş + iskelet (lt≠0) + Null Island muafiyetleri eklendi; yedi feed'lik doğrulamada gerçek sinyal korunur (VBB 462, VlakEShop 10, mdb-1993 6).

## Yanlış pozitif / negatif (asıl tasarım riski)
- **Yanlış negatif:** Eşik yapılandırması çok düşükse yakın çiftler kaçabilir; kardeş peronlar arasındaki gerçek koordinat hataları artık raporlanmaz (bilinçli takas).
- **Yanlış pozitif:** Parent_station kullanmayan düz feed'lerde karşılıklı yol kenarı durakları gibi bilinçli yakın kayıtlar yine tetikler.

- **Ayrıntılı bulgu mesajı:** *"'<name_a>' (kod: '<id_a>') ile '<name_b>' (kod: '<id_b>') arası <dist_m>m — eşik <threshold>m."*

## Ölçülen alan / değer
- `file`: `stops.txt`
- `field`: `stop_lat|stop_lon`
- `line`: ilk durak satırı
- `observed`: `<dist_m>m → '<other_stop_id>'`
- `expected`: `> <threshold>m`
