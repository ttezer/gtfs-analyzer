# STP_022 — stop_code eksik

> Karar: Fiziksel durak ve istasyon kayıtlarında yolcunun tanıyabileceği `stop_code` bulunmalıdır.
> ⚠️ Bu proje `stop_code` eksikliğini kalite uyarısı olarak ele alır; GTFS spec'te `stop_code` opsiyoneldir, bu yüzden spec zorunluluğu gibi yorumlanmamalıdır.

| Alan | Değer |
|---|---|
| Grup | STP — Stops |
| Önem | Orta |
| Sınıf | Quality |
| Aşama | K2 |
| Varlık | Entity |
| Kimlik alanı | `stop_id` |
| Skor tabanı | 1 |
| Görünürlük | VS (`R2`, `R5`, `R9`) |
| Bloke ettiği kurallar | - |

## Tetikleme koşulu (kesin mantık)
K2, `location_type` boş, `0` veya `1` olan kayıtları durak/istasyon kabul eder. Bu kayıtlarda `stop_code` boşsa STP_022 üretilir.

**İki kademeli emit (gürültü kontrolü):**
- `stop_code` **feed genelinde hiç kullanılmamışsa** (hiçbir durakta dolu değil) ve >1 durak etkiliyse → tek **feed-seviyesi özet** (EntityType::Feed, `observed` = eksik durak sayısı). Tek üretici kararının durak-başına on binlerce özdeş notice üretmesi engellenir (STM_017 emsali).
- `stop_code` **kısmen doluysa** (gerçek tamlık boşluğu) veya tek durak etkiliyse → **durak-başına** notice.

## Yanlış pozitif / negatif (asıl tasarım riski)
- **Yanlış negatif:** Giriş/çıkış, node ve boarding area kayıtları kapsam dışıdır.
- **Yanlış pozitif:** Bazı feed'lerde kamuya açık durak kodu olmayabilir; bu nedenle kalite uyarısıdır.
