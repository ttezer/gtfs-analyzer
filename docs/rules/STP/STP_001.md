# STP_001 — stop_id yineleniyor

> Karar: `stops.txt` içinde aynı `stop_id` birden fazla kez tanımlanamaz.
> ⚠️ Bu kural boş `stop_id` değerlerini tekillik hatası saymaz; boş kimlik STP_002, aynı kimliğin tekrar kullanılması STP_001 konusudur.

| Alan | Değer |
|---|---|
| Grup | STP — Stops |
| Önem | Kritik |
| Sınıf | Spec |
| Aşama | K3 |
| Varlık | Entity |
| Kimlik alanı | `stop_id` |
| Skor tabanı | 1 |
| Görünürlük | VS_K (`R1`, `R2`, `R5`, `R9`) |
| Bloke ettiği kurallar | `STP_009`, `STM_002`, `XFL_005`, `PTH_002`, `PTH_003`, `GEO_002` |

## Tetikleme koşulu (kesin mantık)
K3 entity graph, boş olmayan `stop_id` değerlerini `stops.txt` içinde tekil anahtar olarak indeksler.

Aynı `stop_id` ikinci kez görülürse STP_001 üretilir. İlk görülen satır bilgisi mesajda tutulur; sonraki kayıt güvenilir tekil durak varlığı olarak kabul edilmez.

## Yanlış pozitif / negatif (asıl tasarım riski)
- **Yanlış negatif:** Boş `stop_id` bu kurala düşmez; STP_002 tarafından yakalanır.
- **Yanlış pozitif:** Aynı fiziksel durağın iki farklı satırda aynı kimlikle tekrar yazılması spec açısından yine hatadır.

## Mesaj & çözüm önerisi
### R9 Kural Mesajı
- **Kural mesajı:** stop_id yineleniyor
- **Çözüm önerisi:** `stops.txt` içindeki her durağa benzersiz bir `stop_id` verin.

### R2 mesajı/mesajları
- **Ayrıntılı bulgu mesajı:** *"'<stop_id>' durağı tekrarlanıyor (ilk görünüm: satır <line>)."*
- **Ayrıntılı çözüm:** *"Her durağa benzersiz bir stop_id atayın."*

## Ölçülen alan / değer
- `file`: `stops.txt`
- `field`: `stop_id`
- `line`: yinelenen satır
- `observed`: yinelenen `stop_id`

## Kod değiştirirken minimum test matrisi
| Senaryo | Beklenen |
|---|---|
| bütün `stop_id` değerleri tekil | `STP_001` yok |
| aynı `stop_id` iki satırda var | `STP_001` |
| `stop_id` boş | `STP_002`, `STP_001` değil |
