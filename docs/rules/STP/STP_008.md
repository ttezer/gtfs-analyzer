# STP_008 — location_type geçersiz

> Karar: `location_type` sayısal olarak verildiyse GTFS'in izin verdiği `0..4` değerlerinden biri olmalıdır.
> ⚠️ Mevcut K2 kodu sayısal parse edilemeyen `location_type` değerini `None` gibi ele alabilir; bu kartın kesin kapsamı sayısal ama `0..4` dışında kalan değerlerdir.

| Önem | Yüksek |
| Sınıf | Spec |
| Aşama | K2 |
| Varlık | Entity |
| Kimlik alanı | `stop_id` |
| Skor tabanı | 1 |
| Görünürlük | VS (`R2`, `R5`, `R9`) |
| Bloke ettiği kurallar | `STP_010`, `STP_011`, `STP_012`, `TRF_015` |

## Tetikleme koşulu (kesin mantık)
K2 `location_type` alanını `u32` olarak parse eder. Parse edilen değer `0`, `1`, `2`, `3` veya `4` değilse STP_008 üretilir.

Önemli nüans: Sayısal parse başarısız olursa mevcut kod `None` kabul eder; bu kural sadece sayısal ama aralık dışı değerleri yakalar.

## Yanlış pozitif / negatif (asıl tasarım riski)
- **Yanlış negatif:** `location_type=abc` mevcut K2 davranışında STP_008 üretmeyebilir.
- **Yanlış pozitif:** `location_type` boşsa GTFS varsayılanı `0` kabul edilir.
