# STP_009 — parent_station bulunamadı

> Karar: `parent_station` doluysa aynı feed içindeki mevcut bir `stop_id` değerini göstermelidir.
> ⚠️ Bu kural parent'ın varlığını kontrol eder; parent kayıt var ama `location_type=1` değilse STP_010, parent zorunlu olduğu halde boşsa STP_011/STP_032 ayrımı yapılır.

| Alan | Değer |
|---|---|
| Grup | STP — Stops |
| Önem | Kritik |
| Sınıf | Spec |
| Aşama | K4 |
| Varlık | Entity |
| Kimlik alanı | `stop_id` |
| Skor tabanı | 1 |
| Görünürlük | VS_K (`R1`, `R2`, `R5`, `R9`) |
| Bloke ettiği kurallar | `STP_010`, `STP_011`, `PTH_002`, `PTH_003`, `PTH_012` |

## Tetikleme koşulu (kesin mantık)
K4 her durak kaydında `parent_station` dolu mu diye bakar. Dolu değer `EntityMaps.stops` içinde yoksa STP_009 üretilir.

## Yanlış pozitif / negatif (asıl tasarım riski)
- **Yanlış negatif:** `parent_station` boşsa bu kural çalışmaz; gerekiyorsa STP_011/STP_032 devreye girer.
- **Yanlış pozitif:** Parent başka dosyada veya dış sistemde tanımlı olsa da GTFS feed içinde `stops.txt` kaydı yoksa geçersizdir.

## Mesaj & çözüm önerisi
### R9 Kural Mesajı
- **Kural mesajı:** parent_station bulunamadı
- **Çözüm önerisi:** `parent_station` değerini `stops.txt` içinde tanımlı bir `stop_id` ile eşleştirin.

### R2 mesajı/mesajları
- **Ayrıntılı bulgu mesajı:** *"parent_station '<parent>' stops.txt'te tanımlı değil."*
