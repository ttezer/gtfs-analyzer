# ARC_010 — Dosya UTF-8 BOM içeriyor

> Karar: UTF-8 BOM bulunan GTFS dosyası okunabilir olsa da bazı parser'larda ilk başlık adını bozabileceği için kalite uyarısı üretir.
> ⚠️ BOM yok ama başka encoding sorunu varsa ARC_002/ARC_003 beklenir.

| Alan | Değer |
|---|---|
| Grup | ARC — Arşiv / Dosya Seviyesi |
| Önem | Orta |
| Sınıf | Quality |
| Otorite kaynağı | PROJECT_QUALITY |
| Aşama | K1 |
| Varlık | File |
| Kimlik alanı | - |
| Skor tabanı | 1 |
| Görünürlük | VS (`R2`, `R5`, `R9`) |
| Bloke ettiği kurallar | - |

## Tetikleme koşulu (kesin mantık)
K1 dosya baytlarını okuduktan sonra `strip_bom` çağırır. BOM varsa ARC_010 üretir ve parse için BOM'u kaldırılmış baytlarla devam eder.

## Yanlış pozitif / negatif (asıl tasarım riski)
- **Yanlış negatif:** BOM yok ama başka encoding sorunu varsa ARC_002/ARC_003 beklenir.
- **Yanlış pozitif:** Validator BOM'u kaldırarak devam eder; uyarının sebebi başka araçlarla uyumluluktur.

## Mesaj & çözüm önerisi
### R9 Kural Mesajı
- **Kural mesajı:** Dosya UTF-8 BOM içeriyor
- **Çözüm önerisi:** Dosyayı BOM olmadan UTF-8 olarak kaydedin.

### R2 mesajı/mesajları
- **Ayrıntılı bulgu mesajı:** *"'<file>' dosyasında UTF-8 BOM var — bazı parser'lar BOM'u ilk alan adının parçası olarak okur."*
- **Ayrıntılı çözüm:** *"Dosyayı BOM olmadan UTF-8 olarak kaydedin (UTF-8 without BOM)."*

## Ölçülen alan / değer
- `file`: ilgili `.txt`
- `field`: ilk baytlar
- `line`: dosya seviyesi
- `observed`: `UTF-8 BOM (EF BB BF)`

## Kod değiştirirken minimum test matrisi
| Senaryo | Beklenen |
|---|---|
| UTF-8 without BOM | `ARC_010` yok |
| UTF-8 with BOM | `ARC_010` |
| invalid UTF-8 | `ARC_002` |

### Dış araç eşleşmesi
- **2026-07-10 doğrulandı:** MobilityData tarafında UTF-8 BOM'a birebir karşılık gelen notice yoktur.
