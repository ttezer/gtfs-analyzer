# ARC_037 — ID alanında ASCII dışı karakter

> Karar: Tipi `ID` olan bir alanın değerinde yazdırılabilir ASCII (U+0020–U+007E) dışında
> karakter var. Spec bunu **tavsiye** eder: *"Using only printable ASCII characters is
> recommended."* Düşük, Quality, **skor dışı**.
> ⚠️ Dosya başına **tek** notice üretilir; mesaj etkilenen satır sayısını, sütunları ve bir örneği taşır.

| Alan | Değer |
|---|---|
| Grup | ARC — Arşiv / CSV yapısı |
| Önem | Düşük |
| Sınıf | Quality |
| Aşama | K1 |
| Varlık | File |

| Bloke ettiği kurallar | - |

## Tetikleme koşulu (kesin mantık)

Her satırda yalnız spec'te tipi `ID` / `Foreign ID` olan sütunlar taranır (`GTFS_ID_FIELDS`:
`agency_id`, `stop_id`, `parent_station`, `route_id`, `trip_id`, `service_id`, `shape_id`,
`zone_id`, `fare_id`, `block_id`, Fares v2 ve Flex kimlikleri, `record_id`, …).

```
değer.is_ascii() == false  (0x7F üstünde en az bir karakter)
→ satır sayılır, sütun listeye eklenir, ilk değer örnek olur
dosya sonu → ARC_037 (dosya başına bir kez)
```

Dört ayrıştırma yolunun hepsinde çalışır: K1 (genel dosyalar) ve K2 akışları (`stop_times.txt`
— paralel parçalar `merge` ile birleşir — `shapes.txt`, `trips.txt`, `calendar_dates.txt`).

## Yanlış pozitif / negatif (asıl tasarım riski)

- **Yanlış pozitif:** Kural tavsiyeyi ölçer, kusur iddia etmez. GTFS-JP feed'leri ID'lerde
  bilinçli olarak Japonca kullanır (`平日`, `毎日`); korpusta 833 feed'in 591'i Japon.
  Bu yüzden **skor dışı** (`r_noscore!`): görünür, ama puanı düşürmez.
- **Yanlış negatif:** `direction_id` (Enum) ve `jp_*` uzantı sütunları kapsam dışı.
  Yazdırılamayan ASCII denetim karakterleri (U+0000–U+001F, U+007F) ARC_021'in alanıdır.
- Ad/açıklama alanları (`stop_name`, `trip_headsign` …) tipi `Text` olduğu için hiç taranmaz.

## Mesaj & çözüm önerisi

### R9 Kural Mesajı
- **Kural mesajı:** ID alanında ASCII dışı karakter
- **Çözüm önerisi:** ID değerlerinde yalnız yazdırılabilir ASCII karakterler kullanın; ID'ler
  yolculara gösterilmez, görünen ad için name/desc alanları vardır.

### R2 mesajı/mesajları
- **Ayrıntılı bulgu mesajı:** *"'<dosya>' dosyasında <N> satırda ID alanı ASCII dışı karakter
  içeriyor (ör. <sütun>='<değer>'); etkilenen sütunlar: <sütunlar>."*

## Ölçülen alan / değer
- `file`: dosya · `line`: **ilk** etkilenen satır
- `field`: etkilenen ID sütunlarının alfabetik listesi
- `observed`: ilk örnek değer

## Kod değiştirirken minimum test matrisi

| Senaryo | Beklenen |
|---|---|
| `calendar.txt` `service_id=平日` ve `休日` | `ARC_037` ×1, "2 satırda" |
| `stop_times.txt` `trip_id=Tü2` (akış yolu) | `ARC_037` ×1, `file=stop_times.txt` |
| `shapes.txt` / `trips.txt` / `calendar_dates.txt` ASCII dışı ID | her dosyada ×1 |
| `stops.txt` `stop_name=Hauptbahnhof Süd` | **yok** (Text alanı) |
| tamamen ASCII ID'ler | **yok** |

## Teknik ek

### Dış araç eşleşmesi
- **MD karşılığı:** `non_ascii_or_non_printable_char` (WARNING). MD her değeri ayrı sayar
  (bir feed'de 58.206); biz dosya başına özetleriz. MD'nin yazdırılamayan karakter kolu
  ARC_021'e düşer. Korpus run 38363983999: 833 feed, ID alanlarında (`service_id` 836,
  `trip_id`, `stop_id`, `route_id`, `agency_id` …); JP dışı örnek: Lehçe `niedziele i święta`,
  Fince `Kesälinja La-Su`, Almanca `8029103:0:4Süd`.

### GTFS spec referansı
